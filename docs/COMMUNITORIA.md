# Communitoria (Phase 1) — статус и решения

Мессенджер Flōr Group: каналы, сообщения, звонки. **Особый модуль: здесь участвуют
несовершеннолетние** — инвариант безопасности проверяется e2e ПЕРВЫМ, до каналов/сообщений, и
отдельной осью от `tenant:check`.

## Порядок сборки (по ТЗ, не менять)
1. **Граф контактов + инварианты миноров** — ✅ этот чанк.
2. Каналы/сообщения (`mode` явный; ИИ — только `aiSuggestedMode` advisory) — следующий чанк.
3. Звонки (continuous call-инвариант, пересчёт на каждый join/leave) — последними.

## Чанк 1 — что сделано
- **Граф** структурный, read-only: из RBAC (членства) + рёбер `parenthood`. Никакого «поиска и DM
  кому угодно». Эндпоинты `GET /api/v1/comm/contacts[/minor]`.
- **Ребро `parenthood`** (взрослый ↔ КОНКРЕТНЫЙ ребёнок): таблица `Parenthood`. Источник истины —
  **директория Флёруса**; EduStore держит синхронизированное ЗЕРКАЛО. Единственный писатель —
  `ParenthoodSync` (стаб коннектора; домен только читает). EduStore рёбра НЕ авторит.
- **Инвариант приватного DM** (`GraphService.assertPrivateDmAllowed`): разрешение проверяется по
  НАЛИЧИЮ РЕБРА, не по роли:
  - взрослый↔минор — только если взрослый родитель ЭТОГО ребёнка (ребро parenthood);
  - **двойная роль** (учитель-он-же-родитель) — к своему ребёнку по ребру, к чужому минору
    запрещено (роль учителя послаблений не даёт — «строжайшая применимая роль»);
  - минор↔минор приватно — запрещено (безопасный дефолт: миноры в аудируемых каналах);
  - взрослый↔взрослый — разрешено.
  - Наблюдатель в 1:1 невозможен → путь observer относится к многосторонним каналам/звонкам.
- **Инвариант канала с минором** (`ChannelService.addParticipant`): `minorPresent=true` ⇒ участник
  `role=external` НЕ принимается. Enforced на уровне ДОБАВЛЕНИЯ участника (единственный писатель —
  сервис), ДО записи строки — не в UI и не позже. Двусторонне (external→минор-канал и минор→
  external-канал отклоняются).

## Зафиксированные контракты (спрошены, не выдуманы)
- **`parenthood`** — хранение: ребро `Parenthood{ parentUserId, studentId, source }`, источник —
  **Флёрус** (EduStore = зеркало). Решение пользователя.
- **`observerPresent`** — **явно назначенный наблюдатель-сотрудник**: участник с `role=observer`
  (школьный сотрудник). `observerPresent ⟺ ≥1 участник role=observer`. Случайный второй взрослый НЕ
  считается. Применяется в каналах/звонках (чанки 2–3). Решение пользователя.

## Принятые дефолты (feasible-only, не изобретения)
- **минор** ⟺ участник — `Student` (в схеме нет возраста → «несовершеннолетний» = ученик по роли);
  **взрослый** ⟺ `teacher | parent | staff`.
- **external** ⟺ участник без `Membership` в workspace (гость/внешняя сторона).

## Несущие принципы (не нарушать в следующих чанках)
- Секретность: нет исчезающих сообщений, нет «секретных чатов» — полная аудируемость.
- Контур `comm/` изолирован от Документохранилища по умолчанию — вложения НЕ через doc-модуль.
- Совместный холст (если дойдём) — эфемерный, live-only, не персистится в `docs/`, не CRDT хранилища.
- Ассистент/бот (`illness.reported`, `absence.flagged`, `stream.offered`) — события уже в
  мастер-каталоге Архстандарта; сверяться перед тем как писать новые (это чанк ассистента, не сейчас).

## Проверка
- `npm --workspace apps/api run minor:check` — **отдельный** e2e безопасности миноров: (а) родитель↔
  свой ребёнок разрешено; (б) чужой взрослый↔минор без наблюдателя запрещено; (в) external в канал с
  минором отклонён на добавлении; + двойная роль, минор↔минор, взрослый↔взрослый (10/10).
- `npm --workspace apps/api run tenant:check` — изоляция тенанта без регрессий (6/6). Это ДРУГАЯ ось —
  дополнительная, не замещающая безопасность миноров.

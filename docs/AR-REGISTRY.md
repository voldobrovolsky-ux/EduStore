# EduStore — АР-реестр архитектурных решений

> Дата: 2026-07-28. Извлечено из кода и docs/ по состоянию **main** (`cfe3a09`,
> включая PR #10 «учебник → КТП → КПП»). Назначение: дальнейшие спеки и реализация опираются на этот
> реестр, а не на слова. Статусы: **[РЕШЕНО]** — зафиксировано и реализовано /
> подтверждено владельцем; **[дефолт]** — разумный выбор по умолчанию, может быть
> изменён решением владельца; **[узел]** — требует внешнего решения, в спеке
> НЕ считать закрытым.
>
> Компаньоны: [FSM-MATRIX.md](./FSM-MATRIX.md) (матрицы полноты состояний),
> [G-CHECKS.md](./G-CHECKS.md) (исполняемые проверки инвариантов).

## A. Источники истины

| № | Решение | Статус |
|---|---|---|
| AR-1 | Identity, организации, роли верхнего уровня, устройства — **Флёрус** (OIDC, BFF-модель по ADR-0005). EduStore — relying party, свой auth не строит; `sub` = `User.id`. | [РЕШЕНО] |
| AR-2 | Единица изоляции тенанта = **школа = `Workspace`** (`florusWorkspaceId` из claim), ключ `workspaceId` на каждой доменной таблице (57 моделей в `tenant-models.ts`). `Organization` — синглтон платформы, доменные данные на неё не ключуются. | [РЕШЕНО] |
| AR-3 | Ребро `parenthood` (родитель↔ребёнок) — **зеркало директории Флёруса**; единственный писатель — `ParenthoodSync`, домены только читают. EduStore рёбра не авторит. | [РЕШЕНО] |
| AR-4 | **Канон оценок — `JournalCell`**, `Grade` мигрируется и удаляется (решение владельца 2026-07-28). `JournalCell` расширяется полями `source`/`comment`; чтение метрик/отчётов/голоса переводится на `JournalCell`; данные переносятся миграцией; единственный писатель — `grade.posted`. Ворота — G-12. | [РЕШЕНО] |
| AR-5 | Межмодульные факты — **только через transactional outbox** (`OutboxService.enqueue` в транзакции домена). Прямые импорты чужих сервисов и FK между параметрами запрещены (ADR-0001, PARAMETERS §4). | [РЕШЕНО] |
| AR-6 | Журнал EduStore **не является системой записи для госшкол** (273-ФЗ ст.16 ч.3.1, ADR-0002): частные школы — полный журнал; госшколы — рабочий слой + синк-коннектор в гос-ГИС (слот, не реализован). `Workspace.sector` заведён, ветвление пока не читается. | [РЕШЕНО, слот] |
| AR-7 | Права — **данные в БД** (`Permission`/`RolePackage`), каталог версионируется в коде (`catalog.ts`, 35 прав, 6 пакетов) и идемпотентно синкается на буте. Отдельный policy-сервис (OPA/Cerbos) не вводится. | [РЕШЕНО] |

## B. Стек и рантайм

| № | Решение | Статус |
|---|---|---|
| AR-8 | **Модульный монолит** NestJS + Prisma + PostgreSQL; фронт React+Vite; общие контракты в `packages/shared`. Микросервисы не вводятся; единственный отдельный рантайм — ASR (Python/faster-whisper) за анти-коррупционным фасадом `voice`. (ADR-0001) | [РЕШЕНО] |
| AR-9 | Из v1 вырезаны: K8s, Terraform, ClickHouse, OpenSearch, Module Federation, React Native, Python-ML. Вводятся по сигналу нагрузки (критерии — INFRA.md). | [РЕШЕНО] |
| AR-10 | Шина событий v1 — **in-process** (`InProcessEventBus`) + outbox/inbox. NATS JetStream — слот (замена `useClass`). **Граница ввода NATS = второй инстанс API**: `OutboxDispatcher` без `FOR UPDATE SKIP LOCKED` не готов к горизонтальному масштабированию — это осознанный ограничитель, а не баг. | [РЕШЕНО] |
| AR-11 | PK = **cuid** (не ULID из Техспеки), колонки **camelCase** (не snake_case). Консистентно со всеми таблицами; подтверждено владельцем; обратимо через `@map`. (ENGINE.md) | [РЕШЕНО] |
| AR-12 | Хранение файлов — S3-совместимая абстракция `StorageProvider`, **ленивый клиент** (без конфига приложение живёт, файловые операции отдают 503). Загрузка только presigned PUT → commit с HEAD-валидацией. Единственный писатель файлов — `DocModule`. | [РЕШЕНО] |
| AR-13 | ASR — faster-whisper **int8 на CPU, без GPU** (T4 ≈ 610k ₽/мес — разорительно); биасинг словарём класса через `initial_prompt`. Деградация мягкая: ASR недоступен → журнал работает вручную. | [РЕШЕНО] |
| AR-14 | Аутентификация — три жёстко разделённых режима `AUTH_MODE`: `flor` (OIDC BFF), `dev|test|ci` (bypass-заголовки), `pilot-qr` (временный, выключает dev-bypass). Fail-closed при любом ином значении. | [РЕШЕНО] |
| AR-15 | Пилотная сессия (QR) пишется в ту же `Session` и несёт **ту же форму claims, что Флёр OIDC** → RBAC не требует спецкейсов при миграции. Workspace пилота постоянный (`ws-archimed-pilot`). Сверка пилотных `pilot-<hex>` id ↔ реальных `sub` — отдельный миграционный шаг, скрипт не написан. | [РЕШЕНО; миграция — узел, см. AR-33] |

## C. Владение и роли

| № | Решение | Статус |
|---|---|---|
| AR-16 | Две оси ролей: **DOMAIN** (teacher/student/parent/staff — в `Membership`, приходят в токене) и **TENANCY** (operator/org_admin/workspace_admin — у Флёра, в токен НЕ приходят). Каталог прав строится только на доменных; кабинет owner — панель Флёра. **Уточнение AR-35 (2026-07-28): `admin` из `florus_orgs[].role` — организационная роль, ПРИХОДИТ в токен и провижинится в Membership → получает пакет в каталоге (структура школы, устройства, парсер); не путать с tenancy-ролями панели.** | [РЕШЕНО] |
| AR-17 | `staff` маппится в под-роль `{завуч, методист, психолог}` **локально**; назначает школьный админ; приоритет: назначенная ранее → hint из инвайта → `methodist`. | [дефолт] |
| AR-18 | Инвариант **«система предлагает — человек решает»**: Solver→утверждает завуч; летучка→оценку ставит учитель; сдвиг КТП (`ktp.shift.proposed`)→ждёт человека; `suggest-mode`→advisory. Никакой авто-апплай ИИ-результата не допускается ни в одном будущем модуле. | [РЕШЕНО] |
| AR-19 | Разделение обязанностей enforced через RBAC: `planning.*.approve` — только завуч; `lesson.conduct` — только учитель. Учитель не утвердит, завуч не проведёт. | [РЕШЕНО] |
| AR-20 | ИИ-точки — **детерминированные стабы с помеченной точкой замены** (parseTextExtract, Tesseract-стаб летучки, suggest-mode). Замена на реальную модель не меняет контракты событий и таблицы. | [РЕШЕНО] |

## D. Событийная архитектура

| № | Решение | Статус |
|---|---|---|
| AR-21 | Единый конверт `DomainEvent{id, type, occurredAt, workspaceId, correlationId, causationId, depth, actor, payload}`; tenant — в конверте, не в subject; `continuation()` наследует correlation и инкрементит depth. | [РЕШЕНО] |
| AR-22 | Защита каскадов: `MAX_CASCADE_DEPTH=12` (drop + лог), DLQ (`FAILED` при attempts≥8), inbox-дедуп `ProcessedEvent(eventId, consumer)`. Пять рычагов из исследования аналогов (PARAMETERS §1). | [РЕШЕНО] |
| AR-23 | **Единый канон имён событий: `<домен>.<агрегат>.<глаголПрош>.v<N>`** (решение владельца 2026-07-28). События `edustore.*` переименованы одним коммитом (шина in-process, внешних подписчиков нет; опубликованная история outbox — архив, не мигрируется). Версия обязательна. Ворота — линт G-16. | [РЕШЕНО] |
| AR-24 | **Каждый подписчик — через inbox, без исключений** (решение владельца 2026-07-28): дедуп `ProcessedEvent` навешивается централизованно при регистрации хендлера в `EventBus` (рядом с depth-guard), не вручную по месту. Цена — одна строка на обработку; защита от повторной доставки при будущем NATS. | [РЕШЕНО] |
| AR-25 | Чувствительные ПД (мед/соц/риски детей) — **тонкие события** (Event Notification): payload несёт id и тип, данные читаются по правам. Толстые (ECST) — для остального. | [РЕШЕНО] |

## E. 152-ФЗ и безопасность детей

| № | Решение | Статус |
|---|---|---|
| AR-26 | Летучка печатается **кодами-псевдонимами** (не ФИО); гейт идентичности `BriefTestCode` code↔studentId на границах (печать id→code, ингест code→id). Сканы не попадают в Документохранилище. | [РЕШЕНО] |
| AR-27 | Инварианты миноров Communitoria: `external` не добавляется в канал с минором (двусторонне, на уровне единственного писателя `addParticipant`); приватный DM взрослый↔минор — только по ребру `parenthood`; минор↔минор приватно запрещён; двойная роль послаблений не даёт. Проверяются отдельной осью e2e (G-2). | [РЕШЕНО] |
| AR-28 | `mode` сообщения (chat/announcement) — **явный, обязателен в POST**, модель не угадывает и не дефолтит (`400 MODE_REQUIRED`). Полная аудируемость: нет TTL/секретных чатов, правка ставит `edited`, историю не стирает. | [РЕШЕНО] |
| AR-29 | **Consent-гейт — на выдаче производных, не на записи сигналов** (решение владельца 2026-07-28): сигналы копятся всегда (учебный процесс, своё законное основание; потеря истории необратима); `predictive_profiling` гейтит выдачу atRisk/score — ученик без согласия исключается из риск-выдачи с явной пометкой «нет согласия» (не молча) и счётчиком в срезе класса. Ворота — G-13. | [РЕШЕНО] |
| AR-30 | **Охват аудита — по классам действий** (решение владельца 2026-07-28): записи оценок (`grade.posted`), утверждения КТП/КПП, доступ/шаринг/статус файлов, админ-действия (структура, назначения, под-роли), consent/deletion. Сообщения Communitoria не дублируются (контур persist-all — аудит по построению). Retention 3 года, append-only. Erasure-сага — остаётся слотом Фазы 2. | [РЕШЕНО] |

## F. Продукт и рынок (зафиксировано в docs, влияет на архитектуру)

| № | Решение | Статус |
|---|---|---|
| AR-31 | Позиционирование: не замена гос-журналу, а надстройка; продажа модулей «зелёной зоны» (расписание, кабинеты, аналитика, портал, контент). **Оценки/ДЗ — никогда не paywall; без рекламы в детском интерфейсе.** | [РЕШЕНО] |
| AR-32 | Монетизация — `Sku`/`Entitlement` (module/seat/bundle + trial), гейтинг `@RequireEntitlement`. Школам — счёт вручную, self-service биллинга в v1 нет. **Состав SKU v1 (решение владельца 2026-07-28): `lms.core` (весь кабинет учителя+завуча), `param.communitoria`, `cabinet.psych` (когда появится кабинет). Ядро не дробится** — нарезка «модули ≤600k» живёт в договорах, не в коде; гейт на уровне кабинета/параметра. Родительский/ученический доступ — вне SKU навсегда (AR-31). | [РЕШЕНО] |
| AR-33 | Последовательность запуска: пилот «Архимед» (pilot-qr) → Флёр OIDC (код готов, нужны `FLOR_CLIENT_SECRET` + регистрация клиента + миграция пилотных id). | [узел: ждёт стороны Флёруса] |

## G. Узлы, добавленные аудитом 2026-07-28 (закрыть в дизайн-спеке до реализации)

| № | Решение | Статус |
|---|---|---|
| AR-34 | **Tenant fail-closed** (решение владельца 2026-07-28): аутентифицированный пользователь без workspace получает `{tenantId:null, system:false}` → tenant-guard бросает 403 на любой guarded-модели. Кейсы «до выбора школы» (`/me`, provision) — только через явный `runAsSystem` в конкретных сервисах. Owner-кейс не контраргумент: owner — tenancy-роль, панель — Флёр (AR-16). Ворота — G-11. | [РЕШЕНО] |

| AR-36 | **Контракты фронт↔бэк**: `packages/shared` покрывает ~20% вызовов; edu/doc/structure/pilot типизированы дважды. Дефолт: единый HTTP-слой (`http.ts`), все DTO — в shared; прод-хардкод `x-florus-user-id: "teacher-anna"` удаляется. | [дефолт] |
| AR-37 | **REST-префикс**: движок на `/api/v1/edu`, legacy-кабинеты на `/api/<module>`. Дефолт: унификация под `/api/v1` при ребилде кабинетов (план уже в ENGINE.md). | [дефолт] |
| AR-38 | **КТП-авторинг закрыт автогенерацией** (PR #10): `textbook.parsed → ktp.generated` — движок создаёт/дополняет **draft**-КТП (утверждённая версия не трогается, `fgosHours` с бейджем `hoursSource='estimated'`). **Timetable-авторинг (решение владельца 2026-07-28): ручная типовая неделя в кабинете завуча** — экран «Сетка расписания» (класс × день × позиция), CRUD через API движка (движок — единственный писатель, право `schedule.build`). CP-SAT-авторасписание встанет позже за тем же контрактом (Solver заполняет ту же сетку, экран не меняется). Ворота — G-15. | [РЕШЕНО] |
| AR-39 | **`doc.enrich` извлекает текст сам** (PR #10): PDF — `pdf-parse`, `text/*` — как есть; скан без текстового слоя → `textExtract=null` (деградация). Разбор — за абстракцией `ParserProvider`: дефолт `regexp` (0 ИИ), опционально `LlmParserProvider` (OpenAI-совместимый эндпоинт, ключ AES-256-GCM, per-workspace настройка в админке) с fallback в regexp без падения загрузки. Тяжёлый Vision-OCR для сканов — остаётся слотом. | [РЕШЕНО; OCR сканов — слот] |
| AR-40 | **PWA-минимум** (решение владельца 2026-07-28): иконки добавляются; SW остаётся для кеша чтения (школьный Wi-Fi нестабилен); офлайн-мутации — честный запрет: молчаливый optimistic в мобильном журнале заменяется откатом с тостом «нет сети — оценка не сохранена». Полноценная офлайн-очередь — слот. | [РЕШЕНО] |
| AR-41 | **URL-роутинг фронта**: сейчас query-параметры + useState, deep-link только `?pilot=`/`?bind=`. Дефолт: раздел/класс/вкладка отражаются в URL (history), без ввода тяжёлого роутера. | [дефолт] |
| AR-42 | **Порог confidence ASR**: фронт получает `confidence`, но не использует. Дефолт: ниже порога (напр. 0.55) — принудительная дизамбигуация/ручной ввод; порог настраиваемый. | [дефолт] |
| AR-43 | Дублирование логики фронта (journal context vs useMobileJournal; VoiceOverlay vs MVoice; две дизайн-системы `design/` vs `admin/ds/`). Дефолт: единый источник на пару при следующем касании кода; вторая ДС легализуется решением или сливается. | [дефолт] |
